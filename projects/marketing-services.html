Overview

What it does

  • One rules table validates every workflow transition, so the API and UI always agree on what's allowed.
  • Returns and rejections need a reason, and a resubmitted request goes back to whoever returned it.
  • SLA tracking, event-driven email notifications, admin screens and a full audit trail.
  • Dynamic request details stored as JSON so new request types don't need schema changes.
  • Hardened for production: no leaked exception text, a reference ID per request, an origin allow-list and self-hosted fonts.
